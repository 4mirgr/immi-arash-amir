# راه‌اندازی و اتصال سرویس‌ها

## اجرای نسخه فعلی
نسخه فعلی پایهٔ محلی است؛ انتخاب دو پروفایل ورود امن نیست و نباید روی اینترنت منتشر شود.

```sh
npm ci
python -m server.app
# در ترمینال دوم
npm run dev
```

از آدرس localhost که Vite چاپ می‌کند استفاده کنید. API روی 127.0.0.1:8787 است. واردکردن فایل‌ها در فضای خصوصی:

```sh
python scripts/import_documents.py /absolute/path/to/attachment-folder
```

فایل‌های خصوصی و پایگاه داده وارد گیت نمی‌شوند. پس از clone روی دستگاه جدید باید ورودی‌ها را جداگانه وارد کرد. GitHub مخزن کد است، محل ذخیرهٔ عمومی رزومه و ایمیل نیست.

## حساب‌های لازم برای مرحلهٔ آنلاین
۱. در Cloudflare حساب رایگان بسازید؛ پرداخت یا ارتقا به پلن پولی لازم نیست. ساخت حساب به تنهایی اتصال برنامه نیست. پیش از deploy، محدودیت روز و تعداد درخواست را در داشبورد بررسی می‌کنیم. نسخهٔ Python فعلی مستقیماً Worker نیست و برای API ابری به adapter و مهاجرت نیاز دارد.

۲. در Supabase حساب و یک پروژهٔ Free ایجاد کنید؛ نام پروژه و منطقه را ثبت کنید. اطلاعات اتصال را فقط در محیط secrets سرویس قرار دهید، نه چت یا GitHub. پیش از انتقال داده، Supabase Auth برای دو کاربر واقعی، RLS بر اساس auth.uid، storage خصوصی و تست جداسازی دو کاربر لازم است. اکنون پروژه به Supabase وصل نیست.

۳. در Google Cloud یک پروژه بسازید. Gmail API، Google Calendar API و Google Drive API را فعال کنید. OAuth consent screen و Web application client لازم است. callback دقیق را پس از انتخاب دامنهٔ اجرا تعیین می‌کنیم. برای هر پزشک باید رضایت جدا و refresh token جدا دریافت شود. OAuth testing ممکن است محدودیت عمر توکن داشته باشد؛ دسترسی‌های Gmail ممکن است بررسی گوگل بخواهد. اتصال Google در همین چت معادل اتصال OAuth سایت ساخته‌شده نیست.

۴. برای تلگرام از BotFather ربات بسازید؛ توکن را در secret نگه دارید و هر کاربر باید ابتدا ربات را start کند. chat_id باید به همان کاربر متصل و کنترل شود. هنوز رباتی متصل یا پیامی ارسال نشده است.

۵. برای AI، رایگان‌بودن و سقف‌های Gemini API یا Workers AI باید در زمان ساخت حساب و با توجه به منطقه بررسی شود. هیچ API رایگان نامحدود یا دسترس‌پذیری قطعی از ایران فرض نمی‌کنیم. API provider قابل تعویض، cache، محدودیت روزانه و کنترل هزینه لازم است.

## ترجیح ارسال ثبت‌شده
انتخاب کاربر: ارسال خودکار با قالب پیش‌فرض **پس از اتصال**. اکنون فقط draft ذخیره می‌شود. پیش‌نیاز فعال‌سازی: OAuth واقعی، انتخاب CV و template پیش‌فرض، سقف روزانه، جلوگیری از ارسال تکراری، لغو و ثبت نتیجه، فهرست عدم ارسال و queue. این‌ها هنوز پیاده نشده‌اند.

## دامنهٔ .ir و دسترسی ایران
ثبت دامنه در nic.ir و DNS نیاز به حساب مالک دارد. قبل از انتخاب CDN و API از چند اینترنت ایران دسترسی واقعی، TLS و callback گوگل را آزمایش کنید. در صورت نیاز، یک origin یا gateway قانونی و قابل اعتماد با احراز هویت و محدودیت درخواست طراحی می‌شود؛ proxy تضمین دسترسی نیست. گزینهٔ سرور جایگزین می‌تواند هزینه داشته باشد. هیچ DNS یا دامنه‌ای در این مرحله تغییر نکرده است.

## وضعیت مرحلهٔ بعد
احراز هویت تولیدی، دیتابیس ابری و RLS، Gmail/Drive/Calendar دوطرفه، Telegram، collector زمان‌بندی‌شده با سهمیه، بررسی خبر و تطبیق پاسخ‌ها، نسخه‌بندی رزومه با مدارک تأییدشده و بارگذاری امن، PESCI کامل با استانداردهای تأییدشده و تست مرورگر نیاز به تکمیل دارند. جزئیات CV امیر هنوز دریافت نشده است.
