# Interface languages

English and Persian are local interface modes, independent of authentication and provider connections. Each profile keeps its language preference; a non-identifying public preference enables the login/recovery screen. Switching language does not remount editors or change private forms, selected IDs, source quotes, CV/mail bodies or send approvals.

Catalogs in `src/locales/`: core (auth, Google, CV, calendar), opportunities (GP/search/applications), workflows (automation/LinkedIn/PESCI/system messages), evidence (public roadmap criteria). `ui-translations.mjs` merges them, translates complete inline sentences and dynamic fragments, preserves React nodes/handlers and accessibility attributes, and restores Persian on cleanup. Whole strings should be translated before truncation. Unknown copy must get a human English entry; do not hide it or substitute generic English. Raw private/source containers are protected explicitly, not by blanket `dir=auto/ltr` exclusions.

`interface-locale.mjs` selects date/number formatting and signals React rerenders without remounting. English Jalali views remain Jalali with English names/Latin digits. Canonical ISO dates, time zones, option values and form values are unchanged. AI analysis accepts an explicit validated language; English instructions and cache entries remain separate from Persian. Existing user-authored text/history is never rewritten on language change. No external translation service is used. Interface copy is emitted as a separate cached asset so application updates do not force a full dictionary download.

Checks: `node --test tests/cloud_ui_language.mjs tests/cloud_interface_locale.mjs tests/cloud_ai_assistant.mjs`. Optional Playwright/Chromium: `python tests/browser/check_language_runtime.py`, `python tests/browser/check_interface_locale.py`, `python tests/browser/check_english_ui.py`. The full UI census covers both profiles, desktop/mobile, public roadmap and deeper application/calendar forms with synthetic APIs; it rejects remaining Persian interface text/attributes/options, JavaScript errors, overflow and unexpected writes.

Own OAuth result/error pages preserve the requested UI locale without changing identity, redirect or scope rules: Google uses existing encrypted state, LinkedIn a separate strictly validated presentation-only cookie (never an authentication input). The public privacy page follows the non-identifying language preference and has a local switch. No locale change triggers provider actions.
