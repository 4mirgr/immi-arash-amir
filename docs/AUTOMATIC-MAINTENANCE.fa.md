# بازبینی و نگه‌داری خودکار با حفظ ساختار

راهنمای ارسالی `CODEX-EXTENDED-LIBRARY.md` فهرست است؛ دو مدخل مرتبط آن خوانده و با دستورهای جاری پروژه تطبیق داده شدند. نسخهٔ کامل کتابخانه اسکیل اجرایی یا سرویس جدیدی نصب نمی‌کند. دو اسکیل محلی در `.agents/skills/` با مستندات منبع، commit مشخص، مجوز MIT و هش فایل‌ها افزوده شدند:

- `project-code-review`: بازبینی خطا، امنیت، جداسازی مالک، شواهد و نمایش زبان/موبایل.
- `project-tested-maintenance`: آزمون دوره‌ای، بررسی خواندنی سرویس و به‌روزرسانی محدود و آزموده.

فقط اسکیل مرتبط و فایل نقش همان کار خوانده شود؛ فهرست بزرگ را با جست‌وجوی محدود مرور کنید. `python scripts/check_skills.py` اصالت نسخهٔ محلی مستندات را کنترل می‌کند. محتوای اسکیل جدید یا نسخهٔ تازه بدون خواندن و بازبینی وارد اجرا نمی‌شود. هیچ اسکریپت اجرایی upstream نصب یا اجرا نشد.

## چه چیزهایی خودکار هستند؟

۱. آزمون‌ها در push به main، pull request، اجرای دستی و روزانه ساعت۰۴:۱۷ UTC اجرا می‌شوند. تست‌های Node و Python، ساخت عمومی Worker، بررسی اسکیل‌ها، audit وابستگی‌ها و شش مسیر مهم مرورگر جزو بررسی هستند. مسیرهای مرورگر شامل حفظ فرم هنگام قطع اتصال، انگلیسی، نمایش کوچک/بزرگ با فونت۱۳۰٪، فاند، کار مشترک و ارسال دسته‌ای ساختگی است. CI هیچ حساب خصوصی، Secret تولید، ایمیل یا پست واقعی استفاده نمی‌کند.

۲. بررسی روزانهٔ تولید فقط صفحهٔ اصلی پنل، فایل اصلی و اجباری‌بودن ورود را می‌خواند و پاسخ۴۰۱ APIهای خصوصی را می‌سنجد. این بررسی، آزمون معتبر بودن توکن Google، ارسال ایمیل، کیفیت فرصت‌ها، بازیابی پشتیبان یا اتصال واقعی همهٔ scopeها نیست. شکست، خطا ثبت می‌کند؛ داده یا اتصال را پاک یا دست‌کاری نمی‌کند.

۳. دوشنبه ساعت۰۴:۴۱ UTC، یا با اجرای دستی workflow، نسخه‌های پایدار patch وابستگی‌های مستقیم بررسی می‌شوند. محاسبهٔ کاندیدا در پوشهٔ موقت و با غیرفعال‌بودن اسکریپت‌های نصب است. کل تغییر lockfile باید patch باشد؛ major/minor حتی در وابستگی غیرمستقیم، prerelease، downgrade، اضافه/حذف package، تغییر registry یا هویت tarball، رفتار نصب اجرایی تازه و تغییر manifest رد می‌شوند. دستور `python scripts/update_patch_dependencies.py` فقط پیشنهاد را می‌خواند؛ `--write` تنها lockfile معتبر را آماده می‌کند.

۴. کاندیدا پس از نصب قفل‌شده، تمام آزمون‌ها و audit بدون خطای high/critical، فقط در `package-lock.json` commit می‌شود. اگر main در این فاصله تغییر کرده باشد، push متوقف می‌شود؛ force push، دورزدن آزمون یا `continue-on-error` برای گذر اجباری وجود ندارد. عدم وجود patch، تغییر نکردن را گزارش می‌کند؛ خطای registry یا بررسی امنیتی، موفقیت ساختگی نیست.

۵. دریافت و خواندن فرصت‌ها/منابع عمومی همچنان با زمان‌بند Cloudflare موجود، robots، cooldown و سقف مصرف انجام می‌شود. این workflowهای GitHub جایگزین جست‌وجوی فرصت‌ها نیستند. منبع مسدود یا خوانده‌نشده، کامل اعلام نمی‌شود.

## مرز انتشار و تغییر

ساختار پنل‌ها، رنگ و فونت، API، احراز هویت، schema، اطلاعات پزشکی، قواعد ارسال، دو مالک و اتصال‌های Google/LinkedIn با ربات نگه‌داری عوض نمی‌شوند. ویژگی تازه به پیاده‌سازی و بررسی مشخص نیاز دارد. مجوز ارسال یک کار قبلی از وضعیت ذخیره‌شده بازسازی نمی‌شود.

وب‌سایت میزبان در مخزن مستقل خود pin نسخه‌های آزمودهٔ AUS/IntMed را ارتقا می‌دهد و Cloudflare همان ساخت ترکیبی را منتشر می‌کند. اینجا نصب قالب یا مهاجرت فریم‌ورک جدید انجام نمی‌شود. تغییر کد backend Worker نیازمند انتشار جدا با اتصال Cloudflare مجاز است؛ GitHub push به‌تنهایی انتشار backend نیست. این نوبت انتشار واقعی جداگانه بررسی می‌شود، اما برای ادعای «تمام کدهای آیندهٔ Worker خودکار deploy می‌شوند» هنوز مسیر CI دارای Secret اختصاصی انتشار لازم است. کلید دسترسی در کد یا لاگ قرار نمی‌گیرد و ساخت منبع پولی مجاز نیست.

شکست آزمون‌های زمان‌بندی‌شده در GitHub Actions دیده می‌شود؛ دریافت اعلان به تنظیم notification حساب GitHub وابسته است. دامنه و دسترسی از ایران و مهلت آگهی‌ها همچنان باید با شواهد واقعی سنجیده شوند؛ نگه‌داری خودکار تضمین کارکرد همیشگی یا پوشش کل وب نیست.

## اجرا و بازیابی

- محلی: `python scripts/check_skills.py`، `node --test tests/cloud*.mjs`، `python -m unittest discover -s tests -v`، `npm run build`، `node scripts/build_worker.mjs`.
- مرورگر: نصب `requirements-browser.txt` و Chromium با Playwright، سپس `python scripts/run_browser_checks.py`. در CI مرورگر قفل‌شدهٔ Playwright نصب می‌شود؛ محیط محلی می‌تواند Chromium موجود را به کار ببرد.
- تولیدِ خواندنی: `python scripts/live_health.py`؛ هیچ ورودی شخصی لازم نیست.
- بازگشت: revert همان commit تغییر در Git؛ انتشار Worker قبلی و pin وب‌سایت هماهنگ شوند. بازگشت کد، بازیابی بانک یا پشتیبان نیست و اطلاعات اصلی را rollback نمی‌کند.
