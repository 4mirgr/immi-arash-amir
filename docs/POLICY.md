# Project policies
User mandate recorded 2026-11-03: GitHub is canonical; free tiers first; coordinated parallel agents; minimal repeated context; two independent personalized workspaces backed by shared organization data; eventual .ir domain.

## Data and actions
Private profile, CV, mail, calendar, draft and integration credentials belong to their authenticated owner. Shared clinics contain provenance and stable IDs. Raw imports stay outside git even if a repository is private. Public educational cases must be original or licensed and contain no real patient data. A UI profile switcher is a development convenience, never authentication.

Current application sending requires the owner's explicit review and approval of the displayed recipients, sender, CV and letter, individually or as frozen batch/scheduled entries. Earlier `auto_after_connection` planning is historical and is not blanket approval to send applications. Discovery, enrichment and relevant notifications may run unattended under their existing authorization. Transport retains deduplication, idempotency, suppression/unsubscribe, retry limits, audit trail and quotas; unknown outcomes are not replayed. Never infer new CV achievements from recommendations or unverified email; verified structured achievements may generate new versioned drafts. Credentials never appear in logs/browser bundles.

## Evidence
Government, regulators, colleges and universities are primary sources; experience reports are labeled anecdotal. Each claim records URL, checked date, applicability and uncertainty. MMM geography and DPA are distinct. Ranking scores explain fit, never predict acceptance. Imported contacts are leads, not vacancies; search coverage is bounded and disclosed. No authentication scraping or private-group collection without authorized API access.

Automatic public contact discovery is mandatory for every stored opportunity, old or new, across ingestion paths and both workspaces. Each public opportunity URL must have a queue record or an explicit blocked/unavailable/storage status; no fixed first-N subset is considered complete coverage. New imports register the reading task with their opportunity write; the scheduled coverage reconciler repairs missed historical registrations and gradually refreshes outdated extraction versions. Processing remains bounded and source rules apply: missing information is never invented, archived editions are never re-opened, and a newer page/contact is not represented as evidence of an older advertisement. A queued, blocked or unsuccessful task is reported honestly, not counted as a completed lookup. This rule does not authorize sending emails or sharing private account data.

## Cost and availability
Do not promise perpetual free AI, unlimited crawling, continuous agents or Iran availability. Browser refresh 10s reads cached own data; source acquisition uses per-source schedule, backoff, caching, ETag and budget. Never run every external query every 10s. Honor service terms. Use portable interfaces; domain/DNS choice follows measured accessibility from Iran. TLS remains verified; routing/proxies require legitimate configured infrastructure and do not guarantee access.

## Delivery
Publish code and synthetic educational content only. No deployment with personal data until authenticated server sessions, owner isolation, backups and secrets are configured and verified. Status badges distinguish planned, disconnected, local and live. Document unfinished features candidly. Agent task ownership prevents concurrent edits; retain small role-specific instructions.

## Separate Google systems — explicit user requirement
Each doctor must authorize their own distinct Google account. A shared OAuth application/client is permissible, but consent, Google subject identity, encrypted tokens, Gmail mailbox, send identity, inbox/sent/thread records, attachments, extracted contacts, analysis/ranking, synchronization cursors and watch renewals, presets, defaults, quotas and mail queues are owner-scoped. Never reuse the other doctor's token, mailbox or sender as a fallback. No private mail-derived information enters the shared clinic dataset automatically; sharing requires a separate explicit action. A missing, expired or revoked connection blocks only its owner's mail jobs. Binding is derived from the authenticated application user and verified Google identity, never a browser-supplied profile or email. One Google identity must not be bound to both doctors. Display the connected email in each workspace; app-login email and Google mailbox may differ only through that owner's explicit verified connection. Installed chat connectors are separate from the website's OAuth connections. Gmail/Drive/Calendar website connections remain disconnected until implemented and verified independently for each owner.

## Independent LinkedIn and action records
LinkedIn account, encrypted grant, profile snapshots, contacts, metrics, drafts, publication evidence, content schedule and roadmap action notes are owner-scoped. Shared OAuth app credentials never imply shared provider identity. An expired/missing grant blocks only its owner; no cross-account fallback. Manual statistics stay labeled manual; completed planning actions never automatically verify credentials or mutate CVs. Source page availability/change checks never silently renew research conclusions.

CV output follows docs/CV-STANDARD.md: institution-specific forms first, otherwise readable searchable single-column international medical/academic structure; no unsupported achievements or automatic specialization labels. A PDF export is formatting, not credential verification.

Each doctor may authorize an independent secondary Google account for Gmail, with separately approved Calendar events and backup Drive permissions. Amir’s configured secondary email remains constrained; Arash selects his own verified account through owner-bound Google consent. Reconsent pins an already linked secondary identity; changing it requires disconnecting that slot. General Drive tools remain primary-only; server-side mailbox scope keeps tokens, calendar cache/cursors, mail cache and queues separate. Do not replace the primary grant or use a missing sender as a reason to fall back. Supabase profile/CV ownership stays with the actual authenticated user. Before unattended multi-sender campaigns, add owner-level deduplication/suppression across mailboxes; current sends remain explicit. Historical mail search and cached relevance windows are bounded, never claimed to cover the whole inbox.

Unattended transport requires a fresh server-gated check of current verified, non-banned account and membership; stored provider grants alone are insufficient. Missing/unavailable membership checks block transport. Only trusted server callers hold the independent membership-check key; it never reaches browsers or Git. Pending approvals can be cancelled owner-wide without changing another owner or promising recall of in-flight messages. Cache maintenance cannot erase suppression or idempotency receipts.

Clinic correspondence reading uses actual own Sent applications and related threads, with explicit progressive coverage. A panel queue count is never evidence of total Gmail outreach. Minimum durable stop receipts survive raw-mail cache expiry and apply across that application owner's own mailbox slots; private message bodies remain isolated by Google subject. Explicit do-not-contact requests enter the owner's existing outbound suppression system. Follow-up drafts and later send actions recheck the original thread and bounded fresh incoming/DSN searches; a new reply, ambiguity or incomplete history blocks suggested follow-up. Historical negative outcomes are not new vacancies or shared-source evidence.

## Resilient reading and UI recovery

Owner manual GP edits are private versioned prose, not model-verified facts. They retain fixed introduction, closing, salutation and contact signature and bind to the current clinic/source, owned CV and base letter. Changing that context requires a new review. Reusable adaptive templates retain declared focus/tone and a clearly identified example; a later clinic always receives newly evaluated clinic/CV paragraphs. Opaque restoration IDs may be checkpointed for the verified owner, but text, quotes and sending approval may not. Reading user-reported clinical strengths does not certify achievements, outcomes or independent-practice eligibility.

For new job applications discovered in email, the message is a lead. Current public employer/service/contact evidence must corroborate it before ready-to-send recommendations. Research and verified public findings can update that doctor's private clinic bank with provenance; private correspondence is never silently shared. An actual reply remains evidence of communication and can stop follow-ups without being republished as a vacancy.

2026-11-19 owner clarification: list records with usable clinic information first, before pagination, and keep incomplete research last by default; newest-first remains an explicit choice. A first employment enquiry does not require a confirmed current vacancy or a complete clinic dossier. One relevant actually-published clinic/service/team/training fact, a published recipient, a matching owned CV and the owner's confirmed contact signature may support a clearly labelled `initial_enquiry`. Reuse this doctor's fresh, actually-read private clinic-bank evidence with its original timestamps; imported spreadsheet contacts alone are not publication. Never turn an enquiry into a confirmed vacancy, supervision or visa-sponsorship claim. Current applicable restrictions and latest failed employer reads still matter; an unrelated old role's restriction is context, not a permanent clinic-wide prohibition. Mail freshness exceptions apply only to a current clinic enquiry; actual Gmail rereads, source fingerprints, owner isolation, suppression, review hashes and explicit send approval remain mandatory. Marking an item unread changes reading state only and never resets send or notification receipts.

The Arash mailbox mandate includes all own received and sent folders, LinkedIn email alerts and leads absent from the private clinic bank. Archive pages and Gmail history have independent durable cursors; bounded work per invocation never becomes a fixed total-history window. Spam/trash/deleted messages cannot authorize applications. Unsupported/truncated content and history gaps remain explicit incomplete coverage. Only relevant private results are retained; raw unrelated mail is not added to the shared bank. Source-derived draft preparation, notification and application approval remain distinct. New opportunities need fresh source, current owned CV/signature and confirmed recipients before a ready-to-review Telegram alert; opaque deep links require the same authenticated owner. No blanket mailbox-reading mandate authorizes an application send or disclosure to the other doctor.
Transient transport/5xx/status-fetch errors must not erase already loaded same-owner content or be represented as an authoritative provider disconnect. Show the last-success/stale state and retry with bounded backoff, no overlapping identical reads. Verified access denials and actual revocations still fail closed. Session renewal remains in memory, single-flight, and must preserve a rotated refresh credential across temporary membership-bootstrap failure; expired access blocks actions until revalidated. Never replay sends, schedules or other mutations as an authentication retry.

A browser-tab UI checkpoint may persist only allowlisted navigation/filter enums and opaque opportunity/CV IDs, template style and subject index, scoped to the server-verified owner UUID plus profile, with seven-day maximum age. No token, recipient, email/letter/CV text, source quote, draft body, review hash or send confirmation enters that storage. Restore selections only after fetching owned/current records; review and send consent always start unchecked. This checkpoint is neither a data backup nor authentication.
