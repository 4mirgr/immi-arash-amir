# Project policies
User mandate recorded 2026-11-03: GitHub is canonical; free tiers first; coordinated parallel agents; minimal repeated context; two independent personalized workspaces backed by shared organization data; eventual .ir domain.

## Data and actions
Private profile, CV, mail, calendar, draft and integration credentials belong to their authenticated owner. Shared clinics contain provenance and stable IDs. Raw imports stay outside git even if a repository is private. Public educational cases must be original or licensed and contain no real patient data. A UI profile switcher is a development convenience, never authentication.

Sending requires explicit recipient selection and current authorization policy; preferred policy is auto_after_connection (user confirmed); actual sending stays blocked until authenticated transport and sending controls are configured. Before production automatic mode: deduplication, idempotency, suppression/unsubscribe, retry limits, audit trail and sending quotas. Never infer new CV achievements from recommendations or unverified email; verified structured achievements may generate new versioned drafts. Credentials never appear in logs/browser bundles.

## Evidence
Government, regulators, colleges and universities are primary sources; experience reports are labeled anecdotal. Each claim records URL, checked date, applicability and uncertainty. MMM geography and DPA are distinct. Ranking scores explain fit, never predict acceptance. Imported contacts are leads, not vacancies; search coverage is bounded and disclosed. No authentication scraping or private-group collection without authorized API access.

## Cost and availability
Do not promise perpetual free AI, unlimited crawling, continuous agents or Iran availability. Browser refresh 10s reads cached own data; source acquisition uses per-source schedule, backoff, caching, ETag and budget. Never run every external query every 10s. Honor service terms. Use portable interfaces; domain/DNS choice follows measured accessibility from Iran. TLS remains verified; routing/proxies require legitimate configured infrastructure and do not guarantee access.

## Delivery
Publish code and synthetic educational content only. No deployment with personal data until authenticated server sessions, owner isolation, backups and secrets are configured and verified. Status badges distinguish planned, disconnected, local and live. Document unfinished features candidly. Agent task ownership prevents concurrent edits; retain small role-specific instructions.

## Separate Google systems — explicit user requirement
Each doctor must authorize their own distinct Google account. A shared OAuth application/client is permissible, but consent, Google subject identity, encrypted tokens, Gmail mailbox, send identity, inbox/sent/thread records, attachments, extracted contacts, analysis/ranking, synchronization cursors and watch renewals, presets, defaults, quotas and mail queues are owner-scoped. Never reuse the other doctor's token, mailbox or sender as a fallback. No private mail-derived information enters the shared clinic dataset automatically; sharing requires a separate explicit action. A missing, expired or revoked connection blocks only its owner's mail jobs. Binding is derived from the authenticated application user and verified Google identity, never a browser-supplied profile or email. One Google identity must not be bound to both doctors. Display the connected email in each workspace; app-login email and Google mailbox may differ only through that owner's explicit verified connection. Installed chat connectors are separate from the website's OAuth connections. Gmail/Drive/Calendar website connections remain disconnected until implemented and verified independently for each owner.
